# ADR 0003: AR 보조원장 중심 정비와 업무 경계

상태: 사용자 ERP 방향 전환 및 우선순위 순차 구현·단계별 커밋 지시에 따른 진행. 푸시·배포는 승인 범위에 포함하지 않는다. 상세 구현은 에이전트가 아래 최소 범위로 제한하며 과거 구현을 사용자 직접 설계로 소급하지 않는다.

## 목표와 보존

ERP 매출채권·입금 대사 업무를 Java 백엔드 포트폴리오의 중심으로 삼는다. 기존 FREE/유료 정책과 AI 차단은 유지한다. 전역 business_event/daily_review, Python 분개와 tenant AR를 자동 통합하지 않는다. SAP 전체 모듈이나 GL·세무·결제 시스템은 구현 범위 밖이다.

사용자가 승인한 진행 순서는 ①현재 업무 계약과 경계 검수 ②청구 오입력 취소·재등록 ③거래처별 미결·연체 명세다. 각 단계는 검증·독립 검토 후 한국어 메시지로 커밋한다. 당시 입금 복구·Docker·CI 미커밋 작업은 별도로 보존했고, 이후 각각 커밋하여 a93ee7a에서 main에 통합했다.

## 1. 현재 계약 유지와 경계 검수

아래는 실제 소스에서 확인한 기존 계약을 보존한 것이다. 검증 없이 새로운 회계 정책으로 변경하지 않는다.

| 항목 | 유지할 계약 |
| --- | --- |
| 현재 잔액 | 청구/입금 원금에서 취소되지 않은 배분 합계를 뺀다. 원본을 덮어쓰지 않는다 |
| asOf | 현재 전체 장부의 연체 판정 기준일이며 과거 잔액 재현일이 아니다. 기한 다음 날부터 연체 |
| 자료 상태 | 자료 없음·미수0·미배분 입금·합계 일치·개별 반제를 구분한다 |
| 다른 날짜·거래처 | 현재 수동 확정은 제3자 대납·청구 전 입금을 허용한다. 후보 경고와 사람이 검토하는 구조를 유지하며 새 제한을 임의로 추가하지 않는다 |
| 배분 취소 | 묶음 전체를 취소하며 원본/배분 line/감사 이력은 남긴다. 일부 line 취소 API는 추가하지 않는다 |
| 재전송 | 같은 키·같은 정규화 입력은 당시 결과를 재사용한다. 현재 상태는 GET으로 재조회한다 |

검수는 기존 AllocationIntegrationTest를 재사용하고 미래일 문서도 포함하는 현재 잔액 계약, 다거래처 묶음 취소 후 모든 잔액/원본 복원을 보강한다. 기존 합계 대사의 NO_DATA 표현 변경은 이번 AR 작업에 섞지 않는다.

## 2. 청구 오입력 취소·재등록의 최소 범위

분석 보고서의 권장안을 진행 범위로 삼는다. 원본 청구 금액·번호·거래처·날짜는 유지하고 별도 취소 사실에 사유·작성자·시각을 기록한다. 활성 배분이 있으면 청구 취소를 거절하고 먼저 해당 배분을 취소하도록 한다. 취소와 배분 확정은 같은 청구 부모 잠금으로 직렬화한다.

소급 효력일은 받지 않고 현재 장부에 취소 사실을 반영한다. 새 청구는 새 UUID·새 번호를 사용하며 취소한 원문과 연결한다. 기존 번호를 해제하거나 재사용하지 않는다. 취소 문서는 원본 조회에 남기되 현재 미수금·새 후보·새 배분 대상에서는 제외한다. 매출 감액·반품·대손·환불·마감 후 전기는 별도 정책이다. V1~V13은 바꾸지 않고 새 Flyway를 추가한다.

## 3. 거래처별 미결·연체 명세

기존 원장의 현재 잔액을 서버에서 집계한 조회를 제공한다. 과거 시점 잔액으로 표시하지 않는다. 거래처·상태·기한 필터와 잔액 포함 항목을 페이지 조회하며, 합계는 페이지 제한 전에 같은 필터 전체를 집계한다. 취소 청구의 원본 이력은 보존한다.

연체 구간은 새로운 금융 계산이 아니라 dueDate와 명시적 기준일의 날짜 차이를 분류하는 조회 정책으로 제한한다. 구간·기한 당일 처리와 필터 의미를 API 문서에 명시하고 미확정 회계 마감 정책으로 확대하지 않는다. 화면은 웹을 우선하며 승인된 조회 API 범위 밖의 UI 전면 교체는 하지 않는다.

### 적용한 조회 계약

`GET /api/v1/tenants/{tenantId}/receivables/ledger`를 추가했다. 기본 OPEN은 현재 미수 청구, ALL은 취소되지 않은 청구 전체다. 합계는 같은 필터 전체를 읽으며 page/size와 무관하다. 명시적 asOf와 같은 읽기 트랜잭션 snapshot을 사용한다. [API 상세](../RECEIVABLES_LEDGER_QUERY.md)를 따른다.

구간 선택은 사용자에게 별도 선호를 문의했으며 응답 전 기본 조회 분류로 기한 전/당일·1~30일·31~60일·61~90일·91일 이상을 적용했다. 금액·반제·마감 정책을 변경한 것은 아니고 사용자 선택으로 확정됐다고 기록하지 않는다. 완납은 현재 연체일0·SETTLED이며 과거 연체 이력을 재현하지 않는다. 새 명세 화면은 이번 백엔드 조회 범위에 포함하지 않는다.

## 현재 검증 연결

2026-11-16 문서 정리 시점의 재실행은 [검증 기록](../REPOSITORY_VALIDATION.md)을 따른다. V1~V14, Java 220개·클라이언트 26개이며 이전 문단의 V1~V13은 V14 추가 전 보존 대상으로 적은 이력이다. 신규 업무 정책 승인이나 사용자 코드 직접 검토 완료를 뜻하지 않는다.
